# Supported versions and files

## Bazel versions

| Capability | Version contract |
| --- | --- |
| Source-backed Starlark features | Bazel is optional |
| Evaluated targets and repository mapping | Bazel 8.0 or newer |
| Bazelrc grammar and configuration semantics | Upstream Bazel 8.7.0 |
| Bazelrc native flag completion, hover and diagnostics | Catalog reported by a configured numeric 8.7 binary |

The Bazelrc compatibility line is Bazel 8.7. A vendor suffix on that numeric
release does not add vendor grammar support. Other Bazel releases are outside
the support contract; the server neither selects a nearby flag catalog nor
falls back to a bundled one.

## Starlark files

The server recognizes `BUILD`, `BUILD.bazel`, `*.bzl`, `MODULE.bazel`,
`REPO.bazel`, `VENDOR.bazel`, `WORKSPACE*`, `*.scl`, and Bazel query files.
Their exact dialect and role are derived from the path and workspace.

## Bazelrc files

The exact filename `.bazelrc` and every filename ending in `.bazelrc` use the
Bazelrc parser. A differently named regular file also becomes Bazelrc when it
is reached from the published workspace import graph.

The workspace configuration graph starts at the root `.bazelrc` and follows
its reachable imports. System, home and explicit command-line rc files are not
reconstructed.

The dated [Bazelrc behavior inventory](/bazelrc.html#behavior-inventory) states
the exact behavior and boundary of each language-server capability.

## Optional tools

Bazel-backed features use the executable in `bazel.path`. Formatting and lint
diagnostics for Starlark files use `buildifier` when it is installed. Bazelrc
formatting is not supported.
