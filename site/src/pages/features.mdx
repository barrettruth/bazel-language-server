# Features and support

## Editing

- **Diagnostics** report syntax errors as you type. With `buildifier`, lint
  warnings appear alongside them.
- **Formatting** delegates to `buildifier`, using the correct mode for each
  Bazel file type.
- **Semantic highlighting** distinguishes labels, `load()` paths, rule calls,
  and attributes.
- **Structure** includes document symbols, folding ranges, selection ranges,
  and package hints for relative labels.

Open files remain responsive while the workspace index builds. Unsaved buffers
take precedence over disk, and changed BUILD files are replaced in the index
without restarting the server.

## Navigation and refactoring

- **Go to definition** follows labels, source files, and `load()` paths.
- **Hover** shows what a label resolves to and explains unavailable external
  repositories.
- **References**, **document highlights**, and **rename** operate across BUILD
  files. Rename changes the declaration and every source-written label.
- **Document links** expose labels and `load()` paths to clients that render
  clickable links.
- **Go to implementation** follows a `rule(implementation = ...)` assignment to
  its function when both are in the same `.bzl` file.

Labels inside Bazel make variables such as `$(location //pkg:target)` are
navigable and participate in rename.

## Workspace and Bazel

- **Workspace symbols** search targets across the repository.
- **Bazel 8.0+** adds targets whose names are created during macro evaluation
  and resolves external repositories using Bazel's own mapping.
- **Code lenses** offer `build` for targets and `test` for test rules. Commands
  run detached; use a terminal when their output matters.
- **Background refresh** follows BUILD-file changes and package additions or
  removals.

Bazel itself is optional. Without it, the source-backed features stay active;
macro-generated targets and external-repository navigation do not. External
repositories must be fetched before there are files to navigate to.

## Boundaries

Completion, unresolved-label diagnostics, code actions, file-move edits, and
`.bazelrc` support are not available yet. Their dependency order is tracked on
the [Roadmap](/roadmap.html).

Target patterns such as `//pkg:all` deliberately have no single definition.
