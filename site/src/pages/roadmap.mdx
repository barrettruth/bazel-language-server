# Roadmap

Planned work is grouped by what becomes useful together.

## Authoring

1. Keep label-shaped data out of references and workspace edits unless its
   position proves that Bazel treats it as a label.
2. Complete explicit labels from the workspace index.
3. Complete rule names and attributes from exact workspace rule metadata.
4. Show attribute signatures and documentation while typing a rule call.
5. Follow declarations and `load()` bindings across Starlark files.

Rule metadata and source declarations remain separate sources of facts. The
server does not need a general Starlark type checker to provide these features.

## Correctness and repair

1. Report labels that are known not to resolve.
2. Provide document and workspace pull diagnostics.
3. Offer quick fixes for buildifier findings and unfetched repositories.

Diagnostics first prove that a string occupies a label-valued position, then
distinguish a typo from an index that is still loading or a repository that has
not been fetched. Fixes follow only once both distinctions are reliable.

## Refactoring

Rewrite labels when an editor moves a file or package. The editor remains in
control of the move; the language server supplies the accompanying edits.

## Bazel configuration

External system, home, and explicit rc discovery remains separate from the
workspace graph. Converter-specific value validation waits for a source of
semantics exact enough to avoid guessing from display type names; rendering a
final effective option sequence likewise waits for a concrete editor use case.
